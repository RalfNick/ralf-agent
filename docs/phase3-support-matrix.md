# 第三阶段支持矩阵与收口门槛

日期：2026-10-14。第二阶段在本地提交 `695175e`／`0.1.0.dev113` 冻结；第三阶段按本矩阵推进 R21–R24 服务化与治理。第一阶段 dev99 的业务质量、第二阶段的所选编排与执行证据继续按原范围引用。当前阶段尚未验收完成；下面的目标不能当成交付清单。

## 所选部署与边界

| 维度 | 第三阶段所选范围 | 后续或另行验收范围 |
| --- | --- | --- |
| 环境 | Python 3.12、macOS ARM POSIX、本机 Docker Desktop；可信单宿主、单部署所有者 | 跨宿主接管、Windows 生命周期、Kubernetes、HA 与灾备集群 |
| 执行权威 | Local＋SQLite；Temporal＋PostgreSQL EffectJournal，由各自原 Run／Action／History 推进业务 | 新执行后端、由 HTTP 服务或治理库建立另一套业务状态机 |
| 定义与组合 | Agent，以及第二阶段已选择的顺序、图、有限并行、Team／Dynamic 和嵌套子集；策略适用边界须逐项记录 | 第二阶段明确拒绝的 Tool／transform Temporal 图节点、无限递归、通用流式图 |
| 期限 | 有限相对 Run 期限、审批期限；SDK、JSON／TOML 与公共入口配置；Local／Temporal 行为区别需明确并补齐所选链路 | 任意调度日历与无限长期定时任务 |
| 容量与保留 | 部署内、可信 Scope 下的有界准入与容量；原执行额度与未知义务保护；完成数据的保留／清理及活动数据保护 | 跨地域全局调度、通用计费平台、未验收的跨宿主公平队列 |
| 服务与观察 | 原 SDK／A2A 服务基础上的受管理提交、查询、审批、取消、核验与恢复入口；HTTP 持久事件观察、游标续接、有限背压 | Web 控制台、额外 Broker、A2A push、多协议网关 |
| 身份与权限 | 可信宿主认证的调用者映射到明确 Scope；入口授权与资源权限交集、越权拒绝和脱敏审计 | OIDC 联邦、跨企业身份、企业凭证代理等额外集成 |
| 恢复与升级 | 所选 SQLite／Temporal／PG 组合的框架级备份、恢复、迁移／回退责任；固定版本、原 Worker 和原资源证据 | 通用数据库迁移器、任意旧版本升级、自动恢复所有未知外部效果 |
| 质量与采用 | 未改动参考任务沿用原冻结证据；受影响链路重新验证。安装后应用和独立采用另行登记 | 新任务通用质量、性能优势、与 AgentScope／LangGraph 的对等比较 |

单部署所有者不等于所有调用者拥有同一权限。认证后的调用者、Scope 和资源授权仍属于本阶段必需门槛。可选身份协议、部署形式和额外适配器不自动扩张阶段范围；不能据此把基本身份授权、容量或框架恢复删出必需项。

## 全阶段收口

1. 冻结所选部署配置和版本，列明每一条链路的支持及安全拒绝行为；配置别名变化不能改写原 Run 的发布身份。
2. 期限、取消、容量、效果和实际处理器结束分别证明。未知效果保留原义务，通过原核验／停止证据采纳或明确人工处置；不能以清 ledger、TTL 偷占或重发业务关闭门槛。
3. 安装后的完整服务链路覆盖提交、观察断连、审批／过期、重启、重复控制、权限拒绝、关闭与恢复；源码检查不能替代实际服务证据。
4. 备份恢复验证原数据和效果，原版本 Worker 的匹配要求可操作；成功退出进程和拷贝私有备份不等于框架恢复能力已交付。
5. 完成受影响检查、阶段完整回归、固定安装与兼容，登记失败／跳过及尚无证据项，本地提交，不推送远端。

R25／R26 的独立采用与正式质量证据单独管理，不从实现数或测试数推导。完整 R01–R26、通用 AgentScope 对齐与企业正式可用仍有后续目标。
