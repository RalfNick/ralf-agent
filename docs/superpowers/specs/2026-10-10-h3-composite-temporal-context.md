# H3：高级编排与 Temporal 受管理数据上下文

## 目标与边界

图（串行／并行）、Team、动态规划和嵌套编排中的实际 Agent 决策，复用自动历史压缩与大工具结果卸载。Local 原 Run／节点投影、Temporal History 分别保持唯一执行权威。编排策略和 Planner 自身的模型调用不冒充 Agent 上下文链路。

Local 复用原上下文协议；并行节点证据属于原 Run 的节点 execution 投影，预算预留必须隔离节点。新增 opt-in Schema 11，旧客户端拒绝打开，普通原生发布身份不变。

Temporal 增加明确 opt-in 的 managed_context 发布能力。History 分别记录计划、产物读、写派发、写后核验、可选模型摘要回执和快照采纳。写派发后只有读核验，丢失回执不能重复 put 或业务工具。摘要模型只派发一次；收到响应先保存证据再采纳，非法响应用固定 fallback；未知结果保留预算和远程不确定性。默认纯上下文不改变原 History 分支。

## 行为契约

- 保留原始工具结果和调用组；卸载只降低模型输入，不能声称降低 History／数据库体积。
- 每次业务模型派发前核验产物字节、摘要、原始知识引用版本、固定实际组件。
- Scope、namespace、后端与纯策略绑定不可漂移。借用的资源不由 Runtime 关闭。
- 摘要使用独立 1 credit，业务工具和模型预算规则保持原样。预算不足或无须摘要时跳过摘要。
- 取消之后停止新的阶段。准备 I/O 结束后，模型、摘要与产物写通过原 History 原子授权；取消先接受时拒绝尚未获准的调用。授权先接受的操作属于在途，晚到结果仍可入账。未知外部活动不能宣称确认停止或提前释放父额度。
- 不改变已发布纯 ManagedContextPipeline／ManagedDataContext hook 实现身份。

## 验收

实际 Local 图、并行图、Team、动态编排和嵌套执行；节点同名阶段预算无串扰；审批／重启后无重复写、摘要和回执采纳；损坏证据拒绝。
Temporal 分阶段执行测试覆盖写后丢回执、摘要回执后恢复、取消、未知预算、Scope／实际后端漂移，提供真正 Workflow History replay 验证（外部服务不可用时明确记录限制）。同步能力文档、版本和变更记录，完整回归、打包安装检查后本地提交，不推送。
