# Skills Catalog Design

Base ac7b87e/dev77: managed Workspace writes are committed and verified; R01–R26 remains active. Continue inline under the user's standing authorization, local commits only. This architectural increment delivers a replaceable, bounded skill instruction catalog and original managed tools; the dedicated Agent.skills binding role is a separate next increment.

## Intent and boundary

An application should load reference instructions from a versioned catalog, replace the loader/storage, and use them in its custom Agent/Workflow/Team without adding a new execution loop. The local AgentScope SkillLoaderBase/LocalSkillLoader/SkillViewer design separates metadata, loading and progressive access; RALF retains that useful separation while recording loading as original read-only Actions.

Options: automatically inject full instructions into pure Harness would hide I/O and unbounded context; automatically activate named tools would grant permissions from content; parsing an incomplete YAML dialect would silently claim compatibility. Instead, use a small pure SkillSpec, a synchronous replaceable SkillCatalogPort, immutable Memory and frozen POSIX catalog defaults, and original ToolSource list/get. The File default reads an explicit JSON manifest plus ordinary Markdown instruction files. Standard SKILL.md frontmatter loaders can be custom adapters; this default does not claim complete Agent Skills YAML interoperability.

Instructions are untrusted reference data. No process/script execution, tool activation, dependency installation, network permission or workspace permission is granted by text. Associated resources require separately granted Workspace tools. Custom AgentSpec.tools and existing tool_set bindings select the list/get tools; Agent.skills/sandbox/artifacts roles remain rejected until their own binding increment.

## Public contract and defaults

`SkillError(RalfError)` has code `skill_error`. `SkillSpec(name,description,instructions,version="1")` is a frozen pure value; name is ordinary lowercase ASCII slug1..64 (`[a-z0-9]+(?:-[a-z0-9]+)*`), description nonblank ordinary UTF8 at most4096bytes, instructions nonblank ordinary UTF8 at most16777216bytes, version nonblank ordinary UTF8 at most256bytes. Reject NUL and invalid UTF8 before catalog I/O. `to_dict()` returns a detached exact dict `{name,description,instructions,version,sha256,bytes}`; sha256/bytes describe instructions UTF8.

`SkillCatalogPort` has plain finiteJSON `identity`, synchronous `list(scope,*,max_entries=100,offset=0)->dict`, `get(scope,name,*,max_bytes=1048576)->dict`, `close()->None`. Unexpected lazy/awaitable returns are refused by the native Source, not implicitly executed. This is the initial synchronous port; asynchronous database/loader ports need an explicit later contract, not hidden blocking in pure Context.

Pure helpers in skills.py: `skill_metadata(skill)->dict`, `validate_skill_list(value,scope,*,catalog_digest,max_entries,offset)->dict`, and `validate_skill_get(value,scope,name,*,catalog_digest,max_bytes)->dict` validate exact ordinary-type snapshots and detach accepted output, without I/O or authorization grant. Port identity must include a plain lowercase SHA256 `catalog_digest`; default identity additionally pins behavior version, scopes and allowances.

List returns exact `{kind:"skill-list",version:"1",scope,catalog_digest,skills,total,next_offset}`. `skills` contains metadata `{name,description,version,sha256,bytes}` only, ordered by name. Offset plain int0..1000; max_entries plain int1..1000; next_offset plain int or null. Get returns exact `{kind:"skill-instructions",version:"1",scope,catalog_digest,skill}` with full SkillSpec dict. Scope is original `{workspace,principal}`; digest pins ordered metadata including content hashes. Unknown names raise SkillError; denied Scope raises AuthorizationDenied; closed catalog refuses new operations. All snapshots are detached.

`InMemorySkillCatalog(skills=(),*,version,scopes=DEFAULT_SCOPES,max_skills=100,max_bytes=1048576)` validates ordinary SkillSpec entries, uniqueness, max_skills plain int1..1000, max_bytes plain int1..16777216, and aggregate instructions at most64MiB. It is an immutable process default with deterministic content identity; original lock covers list/get/close. Constructor inputs and results do not expose mutable catalog state.

`FileSystemSkillCatalog(root,*,version,scopes=DEFAULT_SCOPES,manifest="skills.json",max_skills=100,max_bytes=1048576)` owns original FileSystemWorkspace. Manifest is at most1MiB ordinary UTF8 JSON with exact `{version:"1",skills:[{name,description,version,path}]}`. Paths use original relative/protected/nofollow/single-link rules and refer to ordinary Markdown text; missing/duplicate/oversized/invalid entries refuse construction with owned cleanup. Original manifest/file read versions, root identity and metadata/content hashes are fixed. Every list/get checks original root and pinned manifest/file revisions; changes raise DefinitionMismatch rather than silently serving a new dataset. Outer original workspace operation owns the entire read/validation interval so actual handler activity prevents close. File metadata is explicit; no recursive discovery, YAML parsing, mtime-only cache or silent refresh. Rebuild a catalog and release to publish changes.

## Source and declaration

`SkillToolSource(catalog,*,version,max_entries=100,max_bytes=1048576)` borrows one synchronous catalog. Identity is exact `{kind:"skill-tool-source",version:"1",behavior_version,catalog,max_entries,max_bytes}`. Descriptor names `skill_list` and `skill_get`; flat schemas constrain list max_entries/offset and get name. Original ThreadExecutionTracker/group retain real synchronous handlers through global loop cancellation. close is async, idempotent and drains started handlers; borrowed catalog is not closed by the Source. Native first scoped operation verifies a bounded complete metadata manifest and ordered digest under original handler ownership; each page/get then matches immutable membership. Public helpers validate local evidence (complete pages also verify digest); partial page/get membership additionally requires that manifest. Native results are verified for exact ordinary JSON types before copy hooks, exact Scope/catalog digest, bounded typed metadata/full instructions and actual sha256/bytes, then detached. Malformed or lazy custom-port outputs are refused, external exception details redacted. Native policies must be read_only; host fixes cost/approval and original Engine enforces them.

Async default `tools/skills-file` factory config exact root/version plus scopes/manifest/max_skills/max_entries/max_bytes/prefix/requires_approval/cost. Pure validation precedes opening files. BuildContext owns original File catalog and Source, drains Source before catalog close, and registers explicit native read policies. JSON/TOML Local/Temporal declarations reuse existing builders. No new dependency, protocol, kernel or authority is needed for these ordinary read-only tools; accepted Run/Release retains full existing tool-source identity. Defaults and22 original starter bytes remain unchanged.
