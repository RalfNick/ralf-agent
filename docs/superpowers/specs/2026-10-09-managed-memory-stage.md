# H3a managed rule-memory stage

Opt-in Local native Agent and sequential Workflow completion stage. The original
Engine owns proposals, budget reservations, receipts and recovery. No new scheduler,
background worker or execution authority. Legacy defaults and release identities
remain unchanged. Graph/Team/Dynamic/nested parents with enabled stages are refused
before admission; Temporal and automatic model selection are subsequent increments.

Host `ManagedMemoryPolicy` binds a borrowed writable CAS backend, namespace,
grounded field allowlist, bounded timeout and one execution credit per proposed
fact. Read-only Facts views cannot be write targets. BindingCatalog stage_policy
supports inherit/ref/disabled; a bound Agent cannot expand host write authority.
The host catalog registration is the grant. Neither model text nor a Facts selector
can create this grant. Policy hooks are synchronous completed proposals.

After output/schema/completion verification and required Session publication,
freeze the adopted final model Action and normalized result. These are completed
result observations, not a promise that the whole Run will succeed: cancellation
or a later local commit failure can leave observations. Provenance says so.
Persist bounded proposals and reserve budget before CAS. Each fact has a stable
Run/node/key identity, fixed source/release digest and expected version zero.
Persist intent before I/O and receipt before settlement; validate exact facts
before confirmation. Failure is auxiliary, never retries confirmed business work.
Unknown writes retain held credits. Recovery inspects unknown intents, never
blindly rewrites them; terminal recovery is query-only and cannot upgrade Run state.
Confirmed stages never redo writes or proposal selection. No paid I/O in this slice.

Enabled runs require atomic optional Store managed_stage_version=1 activation of
semantic schema7. Old dev39 readers refuse schema7; disabled runs retain schemas1–6
and all original manifests. Stage evidence is a separate Run journal, not a fake
business tool Action. Expose borrowed, scope-authorized read-only receipts.

Test gates: stage defaults, per-Agent bindings, hostile/lazy proposals and backend
drift, grounded values, budgets, CAS lost ack/restart, cancellation/real worker
ownership, sequence stages, old/new wheel refusal/recovery, installed public API,
real local Redis and configured PostgreSQL skips, full regression and fresh review.
