# dev123 Linux 基础 SDK 验证计划

用户要求：使用 dev123 安装包，在 Mac 的 Docker Linux 容器中，以 2 CPU、2 GB 内存限制串行运行 Python 3.11、3.12、3.13，记录资源峰值和结果；函数指纹专项与 S2 后置，不推送。

## 范围

- 固定 wheel SHA256 `240ab4e43be5f677ec59934e1a40553236609d7b7156bdf1ff276482b8efc79d`；原推荐制品不覆盖、不重建。
- Linux ARM64、官方 Debian Bookworm slim Python 镜像；记录实际镜像身份和补丁版本，不外推 AMD64 或原生 Ubuntu。
- 每次只运行一个自有测试容器：2 CPU、2 GiB 内存、相同 swap 总上限；所有数据库和测试工作目录位于容器 Linux 文件系统。
- 先安装最小 SDK 并核对版本、依赖和 442 个产品文件，再安装 pytest；安装结束后断开测试容器外网。
- 指定测试来自冻结 sdist，仅复制 tests 与连续示例，不提供 src、Git、宿主凭据或 Docker socket。使用同一固定基础 SDK 清单及两条原 starter 恢复场景；不运行全量或额外真实服务。
- 记录安装及测试期间的 cgroup CPU／内存采样、全生命周期内存高水位、OOM、测试日志／JUnit／依赖／关闭结果。资源数据仅针对本批容器，不代表 Docker Desktop 虚拟机或整机总占用。
- 这是验证任务，不修改产品、不发布新版本、不推送。若发现失败，保留原始结果并归因，不通过修改原 wheel 获得通过。

## 步骤

1. 校验原制品、固定测试清单，准备私有输入和独立证据目录。
2. 依次准备并记录 Python 3.11、3.12、3.13 镜像；对每个版本执行安装、离线测试、starter 和资源监测，确认实际约束及停止后再开始下一个版本。
3. 对照三个版本的收集清单、通过／失败／错误／跳过、资源和停止状态；独立复核证据口径。
4. 保存有限验收记录和校验清单。原 dev123 与后置门槛不变；不将 ARM64 容器结果写成 AMD64／全部 Linux／整个阶段完成。

已执行上述验证，不修改产品或原制品。主矩阵三版本分别为 306 通过／2 失败、308 通过、307 通过／1 失败；各自 308 项，零错误／跳过。定向原 3.11 两项仍失败，3.13 分配追踪定位测试夹具未关闭连接；各版本两条 starter 通过且各业务写入一次。包含诊断的内存内核高水位最大 286.60 MiB，零 OOM。失败记录、初始验证脚本问题和有效补验范围分别保留，不降低门槛或改记通过。
