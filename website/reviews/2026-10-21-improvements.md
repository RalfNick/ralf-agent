- `npm run check`：22 个 Astro 文件，0 errors、0 warnings、0 hints。
- `npm run docs:check`：6 组双语指南与已审阅源哈希一致。
- `npm run build`：16 个静态页面、12 篇双语搜索文档，563 个本地链接／资源与锚点检查通过；私人预览保持 noindex，无虚构 canonical／sitemap。
- `npm run cf:check`：Wrangler 静态资源 dry run 通过，未上传或部署。
- 用当前本地 SDK 生成临时离线工单项目，实际状态依次为 `waiting_approval → running → succeeded`；在新进程 resume，重复提交同一工单返回同一 Run。工具为 `apply_change`，参数与网页示意保持一致。这次使用当前已安装 SDK，没有重新克隆仓库或联网安装模型依赖。
- 实际浏览器覆盖中文／英文 320px、390px 首页与快速开始、1728px 桌面首页、两种语言的审批恢复演示。检查移动导航开关／Escape、语言切换保持指南路径、模型下一步展开、实际复制并粘贴启动命令、搜索加载／无结果／清空及文档入口。

## 第二轮独立复审

对最终文件进行只读复审，逐项追踪原七条建议。复审先发现 Pagefind UI 在界面加载后才异步加载真正索引，原外层 catch 无法处理失败；已改为直接使用 Pagefind API，等待真实查询与结果片段，并增加超时和新实例重试。随后发现搜索过程中清空输入会遗留 `aria-busy`，已修复提前返回的清理。

浏览器故障注入进一步确认 Pagefind 1.5.2 会吞掉查询分块错误并返回空结果。已对确定存在的“审批／approval”增加非空就绪检查；构建脚本强制每种语言只有一个索引分块，并在 README 记录未来扩容时必须调整检查的约束。

最终独立复核结论：**未发现剩余 P1／P2 阻塞项**。已再次确认搜索、请求时序隔离、重试、状态语义和双语内容。网页仍是 Alpha 本地预览；域名、Cloudflare 账户及正式上线继续留待后续配置。
