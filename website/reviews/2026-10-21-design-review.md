# Ralf-Agent 官网设计、文案与交互审阅

日期：2026-10-21。范围：当前 `website/` 的介绍页与入门文档。核对桌面 1728px、手机 390px 的实际页面，以及中英文案和 Python 执行协议。本轮只读审阅页面与实现，新增本报告，未修改网页或 SDK。

整体建议：保留深蓝／青色视觉、执行路径图和精选文档结构；下一轮优先改善准确性、阅读体验与首次上手路径，再调整页面节奏。下文将已证实的问题与设计判断区分列出。

## P1-01：演示阶段被当作真实 Run 状态

**已证实。** 点击“批准操作”后，`RUN DETAILS` 状态徽标显示 `approved`；模拟重启后显示 `interrupted`。它们来自网站自身的 `DemoPhase`，真实 SDK 在批准后将 Run 置为 `running`；进程重启也不是一个同名 Run 状态。左侧还有 `approval_recorded`、`process_restarted`，混用了演示阶段、事件提示与运行状态。

- 位置：`src/components/ExecutionDemo.astro:44`、`src/lib/demo.ts:1`；对照 `../src/ralf_agent/engine.py:1099`。
- 影响：开发者可能把这些字符串用于 CLI／SDK 判断；“浏览器示意”说明没有消除状态字段的语义混淆。
- 建议：把演示阶段与真实 Run 状态分开显示。阶段采用“已批准／宿主重启／继续执行”等人类语言；若保留 Run 状态徽标，使用真实状态语义，并把进程存活与否单独展示。
- 验收：每个被称为 Run 状态的值都能对应真实协议；批准回执与业务完成继续区分。

## P1-02：重要辅助信息与代码偏小，部分对比度不足

**已实测。** 桌面首页代码 10px、能力卡正文 12px；390px 手机首页代码降到 8px，SDK 用量说明 9px，演示范围说明 8px。用量说明的实际前景色 `#5b778e` 与背景 `#080d17` 对比度约为 **4.14:1**；页脚文字约 **2.98:1**。

- 位置：`src/styles/global.css:1202`、`:1233`、`:1424`、`:2249`、`:2286`。
- 影响：恰好把模型密钥要求、供应商用量与“固定数据演示”等必要信息放在最难阅读的层级。
- 建议：介绍页正文以 14–16px 为目标，辅助说明 12–13px；代码优先保持 12–13px，用横向滚动或展开完整示例适配手机。装饰标注可以更小，参与理解或操作的文字不要随之缩小。提高说明文字的亮度。
- 标准依据：WCAG 2.2 普通文字最低对比度为 [4.5:1](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)；14–16px 是本次设计建议，并非 WCAG 规定的字号。
- 另一个手机体验点：语言切换热区约 34×15px，搜索约 17×36px。建议关键控件使用约 40–44px 热区。WCAG 最低尺寸有间距等例外，不能仅凭本次尺寸就宣称全部控件不合规，见 [Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

## P1-03：第一次成功运行的路径不连续

**已观察到页面路径；转化影响属于设计判断。** 首页“开始构建”进入快速开始，第一段又要求访问安装页；安装页在返回快速开始前展开可选 extra。首页最大的完整代码块则要求真实模型凭据，且只展示只读工具，没有延续审批恢复故事。

- 位置：`src/components/Home.astro:22`、`:40`；`src/content/guides/zh/quickstart.md:11`；`src/content/guides/zh/installation.md:32`。英文同构。
- 建议：主入口使用“运行离线示例”，快速开始在一页串起“源码安装 → 生成工单项目 → inspect → approve → resume → succeeded”；可选依赖及真实模型接入作为成功运行后的下一步。保留完整安装页供深入查阅。
- 验收：新访问者从主 CTA 出发，无需跳转其他指南即可完成第一个离线流程；无需密钥的提示与按钮同时可见。仍使用源码安装，不改为未经核验的 PyPI 命令，不承诺未经计时的“几分钟完成”。

## P2-01：首屏产品定位可以更直接

**设计与文案建议。** “让 Agent 的每一步，都能继续”具有品牌感，但完整的“开源 Python Agent 框架”定位仅出现在小号英文标签及 metadata 中。英文 `keep moving forward` 也较泛。

- 位置：`src/components/Home.astro:18`。
- 可选中文方案：
  - 标题：**可审批、可恢复的 Python Agent 框架**。
  - 副文案：用 Python 定义工具，保存模型响应与执行回执；进程重启后，依据已保存记录继续原任务。
  - 主按钮：运行离线示例；辅助提示：Python 3.11+ · 无需模型密钥 · 本地 SQLite。
  - 原口号可保留为次级品牌句，不需要丢弃整套视觉。
- 英文建议：`Durable approvals. Recoverable Python agents.`；演示标题改为 `Pause for approval. Resume from recorded evidence.`。正文与恢复文档继续保留原配置、业务证据及未知效果的边界。

## P2-02：演示缺少可以观察的恢复依据

**设计建议。** 演示说批准绑定原 Action 与操作摘要，但详情只有 Run、工具、参数、效果类别及一句审批提示。用户看不到“为什么这仍是原操作”，也看不到保存与恢复前后的对应关系。

- 位置：`src/components/ExecutionDemo.astro:16`。
- 建议：显示固定 `action_id` 与短操作摘要；重启前后高亮同一组身份及已保存的批准。可加简短事件记录“批准已保存 → 宿主重启 → 读取原记录 → 继续原操作”。
- 完成状态增加“在本地运行这个流程”入口，连接对应快速开始。保持清晰的固定数据示意标记；不把按钮动画描述为真实运行验证，也不扩大 exactly-once 承诺。

## P2-03：核心演示出现偏晚，页面内容可以收紧

**实测布局与设计判断。** 在当前 1728px 桌面，首屏 Hero 高约 894px，执行章节始于页面约 1933px；390px 手机执行章节始于约 2161px。导航有演示锚点，因此不是无法发现，但自然阅读需要先经过装饰图、三条原则和完整能力区。

- 位置：`src/components/Home.astro:25`、`:28`、`:30`、`:38`；`src/styles/global.css:377`。
- 建议：保留主视觉，适当缩短桌面 Hero 的垂直留白；合并“三条原则”与能力区中重复的信息，把交互演示前移。首页完整代码默认展示重点片段，完整文件可展开或进入 SDK 指南。
- 推荐阅读顺序：产品定义与主 CTA → 可交互审批恢复演示 → 工具／编排等能力与实际工单用途 → 最小上手示例 → 精选文档与结尾 CTA。
- 能力展示优先使用仓库里已有的工单示例和可运行模板。

## P2-04：搜索错误文案向访客暴露了开发操作

**代码分支审阅发现，未在浏览器人为制造网络故障。** 搜索 bundle 加载或初始化失败时，界面统一让用户运行 `npm run build`、`npm run preview`。公开网站访客无法执行这些操作，而且加载失败也不一定意味着没有构建索引。

- 位置：`src/components/Search.astro:35`。
- 建议：生产文案使用“搜索暂时不可用，请重试或浏览文档目录”，提供可用的重试和文档链接；构建诊断留在开发环境或控制台。
- 验收：加载失败、无结果、加载中分别有准确反馈；无结果时能清空并改词，失败时能继续访问文档。

## 实施顺序

1. 先修正演示状态语义、重要信息字号与对比度、搜索失败反馈。
2. 再统一首屏定位、按钮文案和一页式离线快速开始，中英文一起更新。
3. 最后重排页面节奏，补充演示中的身份／摘要／保存记录及完成入口。

现有视觉与技术选型可以继续沿用。源码安装、Alpha 状态、浏览器固定数据演示、真实模型用量与恢复边界的说明应继续保留。转化效果相关建议属于设计判断，仍需上线后的真实行为数据验证。
