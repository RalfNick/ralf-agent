# Temporal deployment dispatch and original ancestry

This implements the next dependency of the required full deployment-admission gate. The Registry foundation remains in its original History. Original Run/Parent History owns business and child intent. This slice adds worker-only execution admission, not public Engine/Profile activation or safe release.

## Selection and compatibility

Internal `TemporalRuntime(_deployment_admission_policy=DeploymentAdmissionPolicy(...))` pins the exact immutable policy object and identity. Omission leaves the original default Manifest byte-compatible. `deployment_admission_protocol={version:1,policy:<full identity>,registry_id:<stable address>,implementation:<fixed source inventory>}` is published and validated. Publication inventory covers the new state/protocol/transport and the integration modules. Workflow validation checks its shape without reading local files; Worker validation compares its current publication and refuses drift.

The selected internal worker supports ordinary Agent/sequence and registered graph/Team/Dynamic/nested definitions, existing non-Coding per-Agent data/context components and Session writes. Selected Coding execution and SDK Session-coordinator Turns explicitly refuse in this slice: their physical-close and coordinator-admission transports require the following integration. They remain required full-delivery work, not removed from the phase-three matrix. Public `TemporalEngine` rejects the selected manifest and Profile admission stays rejected. Actual service validation uses the original SDK directly, not an Engine exemption.

## Accepted metadata without changing requests

Both original Workflow initializers consume `accepted.deployment_admission={version:1,root:<original held-unbound reservation root>,lineage:[<links>]}` beside `request`. Request, command and child projection digests keep their original meaning. Selected releases require this metadata; unselected releases refuse its presence.

The root record is the original Registry reservation, including proof digest; it must have exact fields, state held-unbound and execution_epoch None. Its policy/registry address, Scope, namespace, original root address and request/Manifest digests match the accepted Run. Root SDK parent must be absent. All selected Runs require actual current SDK epoch equal to original execution epoch, and actual namespace name equal to the root namespace. Reset/retry cannot replace the original execution.

Each lineage link has exactly `parent_run_id`, `parent_execution_epoch`, `parent_request_digest`, `parent_manifest_digest`, `call_id`, `child_run_id`, `child_command_id`, `child_request_digest`. The bounded path starts at the root, connects each previous child to the next parent, has no repeated Run IDs, and ends at this accepted child. Its immediate actual SDK parent namespace/ID/epoch must match. The selected execution policy bounds depth (at most eight for this protocol).

## Pure original-History interfaces

New `temporal_deployment_execution_state.py` supplies:

- `initialize(state, metadata, *, namespace, epoch, original_epoch, parent)`; parent is None or exact `{namespace,workflow_id,run_id}`. Store immutable metadata, original SDK tuple and `deployment_receipt=None`. Require/deny metadata according to the fixed selected release before business.
- `view(state) -> dict`: selected original proof with exact fields `version`, `scope`, `run_id`, `command_id`, `execution_epoch`, `original_execution_epoch`, `namespace`, `request`, `request_digest`, `manifest`, `manifest_digest`, `admission`, `admission_receipt`, `children`, `proof_digest`. Children are detached original Parent records, including admission metadata and pinned child epoch; leaves have []. Scope authorization remains the existing Workflow query guard.
- `activity_request(state) -> dict`: fixed `{scope,run_id,execution_epoch,command_id,request,runtime_manifest,deployment_admission}` for the admission Activity.
- `adopt(state, result) -> None`: validate exact response `{version,run_id,execution_epoch,root,metadata_digest,proof_digest}`; root is the exact held-bound original Registry record with original root SDK epoch. Persist once, exact retries idempotent, no caller-provided boolean can authorize dispatch. `admitted(state) -> bool` is true only after adoption.
- `project_child(state, call) -> dict`: only admitted original Parent, same immutable root, append one exact link from its recorded child request/intent; never mutate request or reserve another root slot.
- `pin_child(state, payload) -> dict`: exact `{scope,parent_run_id,parent_execution_epoch,child_run_id,child_execution_epoch,child_request_digest,metadata_digest}`; authorize original parent/child record and dispatched intent, persist immutable `deployment_execution_epoch` in the original child record. Same evidence retries; conflicting epoch refuses.

## Actual SDK transport and universal Worker guard

New `temporal_deployment_execution.py` supplies fixed Activity `ralf.temporal.deployment-admission.v1` and:

- `admit(runtime, client, value, info) -> dict`: verify Worker pin and actual Activity Workflow ID/current epoch/namespace; query the epoch-pinned original Run/Parent proof and SDK description; retrieve live namespace UUID. Validate root reservation and entire bounded original ancestry, match every parent's exact child intent/request/metadata and SDK parent relation, then bind the original root epoch in the existing deployment Registry. Query the original held record after binding; compare all evidence before producing the adoptable response. No business I/O, no release.
- `validate_activity(runtime, client, request, info) -> dict`: follow the Worker's fixed selected policy, not a caller's optional flag. Resolve Scope from the ordinary payload or original model-adoption payload, query actual original History and require already-adopted admission; validate ancestry, namespace and held Registry binding. Do not accept a dropped manifest or forged admission payload as an exemption.
- `control(runtime, client, value, info) -> dict`: verify actual original Parent and exact child intent; register returns original intent acknowledgment without any Registry child/root reservation. Observe/cancel/recover use the fixed child SDK execution and original command/query interfaces, never an Engine bypass. Pin a discovered child epoch through the original Parent Update. Validate original child identity before trusting a business observation.
- `registered_activity(runtime, client)` and `wrap_activities(runtime, client, activities)`: register the admission Activity, and wrap every other Activity, including model/tool/context, ACK/reconcile, limits/completion, Parent selection/control and Session I/O. Exempt only the fixed admission Activity; it validates actual SDK identity itself. Use exact mechanical carrier `{scope,_deployment_activity_request}` for selected business Activities: guard its Scope against actual SDK History, then pass the unchanged inner request to the original handler. Never append headers after original stage/action request digests have been frozen. Malformed carriers and wrong outer/inner identities refuse; the carrier never exempts authorization. Detach inputs before awaiting and recheck runtime after validation/body. Existing mechanical Activity owner wrapping remains outermost.

Both Run and Parent loops gate before first business Activity, reservation-producing `next_operation`, selection or child start. Admission failure keeps queued business and held quota, emits sanitized diagnostics, waits for original recovery; no automatic external-effect replay. Original deadlines may cancel business while gate awaits, but do not release quota. Parent records its original child intent before projection and rolls the new record back if projection refuses; it persists projected metadata beside that original record, passes it in SDK child acceptance and pins original start epoch. Selected business payloads carry Scope in the mechanical carrier; actual Run/epoch come from SDK info and original History. Inner payloads and default payloads remain unchanged.

## Required evidence and remaining gate

Tests prove strict metadata, altered policy/namespace/root/request/Manifest, direct SDK orphan/forged parent/replaced epoch, no request mutation, child intent and pin idempotence, all Activity categories guarded, dropped flags refused, default byte compatibility and public preflight refusal. Actual Service proves root Agent/sequence and graph/Team/Dynamic/nested business only after SDK admission, one Registry root for descendants, Worker absence/restart, held claims across approval/cancellation and replay; independent installed package repeats selected evidence. Unknown effects and physical release are not inferred from those results.

No release operation is added. Public assembly, uncertain-start receipt recovery, Coding physical ownership/coordinator Turns, root closure proofs and safe release remain required next delivery. Old experimental publications retain matching original Worker/source; default original History compatibility must be verified independently.
