## Immutable binding and bound

After the Activity, Registry commit rechecks full-Scope command identity, original
submit record, first verified target epoch and per-Action slot. One slot per
`(Scope,target,original epoch,Action ID)` is shared across all caller IDs/results.
Concurrent proofs cannot take it twice. A fresh later epoch cannot acquire new
slots for a previously pinned target. Exact repeated commands return the detached
original receipt/binding before remote proof, including via normal Signal reads.
The SDK validates Scope and namespace name/UUID and sends the Run command to that
original epoch. A wait failure never undoes a durable reservation.

Let M be the verified ordinary Action inventory across original accepted Run
Histories. Extra manual records are at most M; retry/Started count and credits do
not create slots. Normal+cancel+drive records remain bounded by3C, so total is
at most3C+M. No fixed4096-per-Run bound or History/Update traffic bound is claimed.
No original identity is deleted. Registry admission remains `not_applied`; only
the original Run adopts business evidence. Manual evidence is not handler stop,
effect ACK, parent settlement or retirement.
